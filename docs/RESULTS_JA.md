# 実測結果と再現範囲

この文書の数値は同梱プログラムの実行結果です。論文の表の数値を転記したものではありません。
測定日：2026-09-30。公式参照コミット：`47b6ce98fb53534871da4e4bead739ac7d170091`。

## 1. 何を検証したか

C++コアの23ケースは全て成功しました。CTestでは1つの実行ファイルにこの23ケースをまとめています。
Releaseビルドに加え、AddressSanitizer + UndefinedBehaviorSanitizerのビルドでも23ケース成功し、
サニタイザ診断はありませんでした。サニタイザ検証はOpenMP OFF / NATIVE OFF / Debugビルドです。
並列版については通常ビルドで1対4スレッドの比較をしていますが、ThreadSanitizerは実行していません。

検証項目は、L1カーネルと正定値性、確率行和、異なるsource/target数、5次元、streamingと明示Uの一致、
縮約解法と完全行列解法の一致、重み付き二乗誤差、有限差分勾配、ElkanとLloydの一致、
空クラスタ・重複点、完全ランクNyström、近似カーネルの因子分解、目的関数の各ブロックでの減少、
targetの並べ替え、極小分散、ゼロ質量、未知点への変形、入力異常、CSV/ASCII PLY往復です。
加えて UOT の1対1閉形式・可変質量、および共通正規化・Student-t MM・変形写像を検査します。
細目と許容値は `tests/test_core.cpp` にあり、実行ログは `pixi run test-cpp` で再生成できます。

## 2. 公式Pythonを実際に動かした比較

`tests/upstream/fuzzyclusterreg.py` は公式ファイルとGit blob SHA-1まで一致しています。
SHAは `0df3a88bb5d855674f3617fb04f2664289f9c2d6` です。
同じランドマークを使うため `_kmeans` の返す中心だけを固定し、公式INysと反復関数は変更していません。
同じ正規化済み点群から16反復を比較しました。固定回数比較では公式 `tol=-1.0` にして
収束判定だけを抑制しています。C++側は `official` モードです。

| 3 | 83 / 64 | 4.788e-12 | 4.826e-12 | 3.296e-16 |

この比較は、同じランドマークと有限個の入力についての数値的一致です。

比較するTは正規化後の座標です。全反復のlossも検証していますが、公式のlossは整合目的関数Jとは区別します。

## 3. CPU速度とメモリ

環境はIntel Xeon Platinum 8573C、GCC 14.2、Eigen 3.4.0、Linux x86_64です。
OS上は5論理CPUが見えますが、cgroupのCPU割当は約4コア相当です。
Release、倍精度、`-O3 -march=native`、OpenMPを使用しました。BLAS/MKL/GPUは使っていません。
ウォームアップ後の3回の中央値です。生値の最小・最大と全実行はCSVに残しています。

比較条件は3次元、source数=target数、**同じランク128、同じ12反復、同じデータとseed**です。
「全U基準」は今回作成した全確率行列保存版で、変形ソルバは高速版と同じ縮約解法です。
**公式C++/MKL実装に対する速度向上ではありません。**

| 各点群の点数 | 全U基準・1スレッド (s) | streaming・1スレッド (s) | streaming・4スレッド (s) | 基準→4スレッドの倍率 |
|---:|---:|---:|---:|---:|
| 512 | 0.128255 | 0.046761 | 0.032472 | 3.95× |
| 2,048 | 3.464823 | 0.693362 | 0.272589 | 12.71× |
| 4,096 | 16.501332 | 2.722706 | 1.065000 | 15.49× |

4,096点では、1スレッド同士でも約6.06倍、4スレッド版では約15.49倍でした。
全速度実験での登録座標の最大絶対差は `2.176e-14` です。計算を近似して速度を出した比較ではありません。
ただし両方式とも同じNyström近似を使用しており、完全カーネルとの差がないという意味ではありません。

時刻は `fit()` 全体（正規化・ランドマーク構築・反復）を計測しています。
人工データ生成、ファイルI/O、RMSE算出を含めていません。

| 各点群の点数 | 全U基準のpeak RSS (MiB) | streaming・4スレッドのpeak RSS (MiB) |
|---:|---:|---:|
| 512 | 8.125 | 4.805 |
| 2,048 | 82.293 | 9.156 |
| 4,096 | 293.734 | 15.469 |

メモリは `/usr/bin/time` の**CLIプロセス全体**の最大常駐メモリです。
4,096点では約293.7 MiBから15.5 MiB（約19分の1）になりました。
これはアルゴリズムだけのメモリアロケーション量ではありません。
source/targetとも4,096点の完全なUは1枚だけで128 MiBになり、基準にはほかの一時行列もあります。

`r=0.3N` を維持すると記憶量は二次で、ここでの固定ランク128とは条件が違います。
また、全対応を評価するE-stepの時間は `O(MNd)` のままです。100万点にそのまま適用できるとは主張しません。

## 4. 人工データの位置合わせ精度

人工データはC++で生成します。2Dは非対称な閉曲線、3Dは非対称な楕円体状の表面です。
既知の非線形変形、平行移動、targetの順番のシャッフルを加えます。
ノイズはtargetの座標に加える独立ガウスノイズ、欠損はtarget点のランダム削除、
外れ値は各座標 `[-3,3]` の一様分布です。sourceには真の対応を与えません。
変形式は `src/synthetic.cpp`、正解座標は各例の `truth.csv` にあります。

以下はseed=7,42,123の平均で、paperモード、論文の既定ハイパーパラメータ、ランク比0.3、
最大50反復、1スレッドです。誤差は正規化前の座標単位です。
「非剛体変形前」は**重心とスケールを合わせた後**であり、単なる平行移動の修正による改善を除いています。
GT RMSEはノイズなしの真の対応座標を基準とし、欠損した点を含む全sourceで評価します。
NN RMSEは登録sourceから観測targetへの最近傍誤差です。

| ケース | source点数 | 非剛体変形前GT RMSE | 登録後GT RMSE | 登録後NN RMSE |
|---|---:|---:|---:|---:|
| 2D・ノイズなし | 256 | 0.105945 | 0.047067 | 0.004859 |
| 3D・小変形 | 512 | 0.035107 | 0.002863 | 0.004421 |
| 3D・ノイズあり | 512 | 0.093689 | 0.068847 | 0.035292 |
| 3D・targetを20%欠損 | 512 | 0.094956 | 0.078091 | 0.060507 |
| 3D・大変形 | 512 | 0.282435 | 0.198771 | 0.050956 |
| 3D・target外れ値約10% | 512 | 0.353214 | 0.940657 | 0.376731 |

**外れ値約10%では悪化しました。** 個別正規化の重心・スケールも外れ値の影響を受け、
その後の非剛体登録も外れ値に引かれています。公式モデルにない外れ値分布やロバスト損失を追加して
失敗を隠すことはしていません。このケースでは、正規化前のGT RMSEも約0.2488なので、
単なる評価基準の違いで悪く見えているだけではありません。

小変形の回復は良好ですが、ノイズ・欠損・大変形では真の対応の誤りが残ります。
2D例は輪郭としてはよく重なっても、GT RMSEは約0.047でNN RMSE約0.0049より大きい値です。
点群としての一致と、物体上の同じ点の追跡を区別する必要があります。

全seed、両モード、各誤差の標準偏差は `quality_raw.csv` / `quality_summary.csv` にあります。
6ケースのseed42・paperモードの入力・正解・結果・履歴は、ベンチ再実行先の `examples/` に保存されます。

## 5. ランクを上げれば登録精度も良くなるか

次は3D、1,024点、seed42、変形振幅0.25、ノイズ標準偏差0.003の単一例です。
ランク変更は近似誤差だけでなく変形モデルの自由度と最適化軌跡も変えます。

| ランク | カーネルの相対Frobenius誤差 | GT RMSE | NN RMSE |
|---:|---:|---:|---:|
| 32 | 0.409737 | 0.008590 | 0.009888 |
| 64 | 0.253689 | 0.015039 | 0.009976 |
| 128 | 0.150862 | 0.029465 | 0.013175 |
| 308 | 0.078748 | 0.038665 | 0.014330 |
| 1024 | 3.95369e-15 | 0.041086 | 0.011049 |

カーネル近似は改善しましたが、GT登録誤差は悪化する例になっています。
したがって、「低ランク近似の誤差境界が良いから真の対応も正しくなる」とは言えません。
この実験のランク別実行時間は収束までの反復数が異なるため、固定12反復の速度比較と混ぜません。

## 6. 理論的忠実性と未検証の範囲

paperモードでは、共通等方分散へ整理した目的関数の各変数更新を導出し、4ブロックの減少を数値検証しています。
公式と同じ低ランクカーネルに対する縮約方程式は代数的に同値です。
一方、公式のeps加算・古いTでの分散更新・停止lossは同じ目的関数の厳密な交互最小化とは分けて扱います。

補足資料の次元なしLipschitz中間定数については反例をテストしています。
3Dの小変位例で印刷定数に対する比は約2.999964です。安全なL2評価には次元係数が入ります。
これは**最終Nyström誤差境界そのものを否定する反例ではありません**。
詳細・式・留保は `THEORY_JA.md` §7 を参照してください。

FAUST/TOSCA、論文の各表の成績、公式C++/MKLの速度、MATLAB実行、Windows/macOSは未検証です。
本書§3の clustering 速度表は CPU のみです。一方、UOT の CUDA 経路は RTX 2070 上で
Gaussian/Student-t の CPU 一致、memcheck、racecheck、実行時間を別に確認しています。
条件と数値は [SINKHORN_IMPLEMENTATION_JA.md](SINKHORN_IMPLEMENTATION_JA.md) §11 を参照してください。
大域最適性、対応の一意性、微分同相性、任意の初期姿勢や外れ値に対する成功は保証していません。
大きな剛体回転を自動で解消する前段も追加していません。

## 7. 再実行

ビルドはルートの `README.md` を参照してください。測定と同じCPU最適化には `CLUSTERREG_NATIVE=ON` を指定します。

```bash
pixi run test
pixi run python scripts/benchmark.py --exe build/pixi/clusterreg_cli --out-dir build/results/reproduced_experiments --repeats 3 --max-n 4096
pixi run python scripts/plot_results.py --results build/results/reproduced_experiments --out build/results/reproduced_plots
```

サニタイザ検証の例：

```bash
pixi run test-sanitize
```

乱数seedは固定していますが、標準ライブラリ・CPU・コンパイラによる乱数分布実装と浮動小数点の違いは残ります。
そのため異なる環境でビット一致や同じ速度を保証するものではありません。
